Style switch… Alternative style sheets polyfill

Script capable of:
  1. Automatically loading styles from the document
  2. Building a form control that lets you switch between different styles
  3. Setting the default selection based on the chosen style, including a listener that updates the form control live based on OS settings and cookie value
  4. Saving the selected style to a cookie when changed via the form control
  5. An optional listener for the cookie that allows live style switching to the chosen style. (It is in a separate JavaScript file and is not required if you prefer a backend/server-side solution)

In the upper-left corner there is a list of loaded styles. Out of the 3 possible sheets, either 1 (persistent) or 2 (persistent + alternate or persistent + preferred) are loaded.

Minimal working setup

The script supports many types of configuration and customization to meet a wide range of requirements. If you do not need customization, the basic script only requires inserting one line of JavaScript into the document:

					
<script src="./style-switch.mjs?v=1.0" type="module" integrity="sha256-n06EtXgbhG4A71ozlM7XoNLcHk08TfttEMDpmLjiEM8="></script>
Something extra… cookie change listener

The result of this script is storing a cookie in the browser. You can respond to this cookie value in several ways, typically on the server side or with JavaScript. If you choose JavaScript, one solution is provided as part of this project:

					
<script src="./style-switch-cookie-listener-example.js?v=1.0" integrity="sha256-CJNHv370jlgrCgbvYufk258TKe7tXWU1fBGBBgQXqrE="></script>
Possible problems?

A common issue is the .mjs file extension, which does not usually have the correct MIME type 'text/javascript' configured. If this occurs, there are two solutions. Either rename the file extension from .mjs to .js (and update the paths referencing the file, such as in example-usage.html), or adjust the web server configuration to assign the MIME type 'text/javascript' to .mjs files.

What are the other files for?

The already mentioned style-switch-cookie-listener-example.js is clear: it listens for cookie changes and switches the active CSS stylesheet accordingly. Whether you need it depends on your setup. It is useful to have, but you can alternatively use your own backend/server-side solution. The other files are not required for StyleSwitch; they are only examples, helpers, or configuration checks. You can safely delete them if you do not need them and you do not have to include them in the project where you use StyleSwitch.

The files included are:

  • example-usage.html an example of using StyleSwitch.
  • content-type-checker.js, checks server configuration to ensure all file extensions have the correct MIME type. A common problem is the .mjs extension missing the correct MIME type 'text/javascript'. If this happens, you can either rename the extension from .mjs to .js (and update file paths, such as in example-usage.html) or configure the web server to assign the MIME type 'text/javascript' to .mjs files.
  • modules/string/interpolate.mjs, used only by content-type-checker.js, it allows inserting variables into text strings and outputting them.
  • modules/importWithIntegrity.mjs, a script enabling dynamic module import with file integrity checking. It is also used only by content-type-checker.js.
  • readme-screenshots folder, screenshots mostly from the browser console.
  • example-css folder, CSS styles used for example-usage.html. Based on MVP.css
  • README.md library description in Markdown
  • README.html the same description in HTML format
Detailed possible settings:

styleLinksQSA

(string) Value for document.querySelectorAll() used to load styles. You will probably not need to change the default setting.

rootElementQS

(string) Value for document.querySelector(), the element into which the resulting widget created by this script will be inserted.

cookie

(object) Cookie settings used to store the user's chosen page style.

texts

(object) All text labels for the widget.

nakedStyle

(object) Allows adding a style without CSS as one of the available page appearance options, called naked style. The object details are:

  • (bool) use whether to use the naked style.
  • (object) celebrateNakedDay:
    • (bool) switchAutomatically automatically enable and disable the naked style on the specific date defined by the following values
    • (number) monthNumber month number for naked day (months start at 0, so January is 0)
    • (number) dayNumber day number within the month.

resultSnippetAppearance

(object) All appearance and behavior settings for the resulting widget that this script creates and returns in the (object) return value. The object details are:

  • (string) idPrefix prefix for the resulting widget's id. A random string is added so the id is unique and the widget can appear multiple times in the document if needed.
  • (string) defaultResultSnippetElement type of element that will wrap the resulting widget.
  • (string) outputFormat The form control type the script creates as output. You can get this list from the static read-only method StyleSwitch.OUTPUT_FORMATS, the options are:
    • switch (input type checkbox), possible only when you have exactly 2 available appearance styles, for example dark and light.
    • select (default setting)
    • radioList … a list of radio input items
  • (string) preferredColorSchemeChangeBehavior default behavior of the widget when the operating system color scheme changes. The widget can dynamically switch the page style immediately on OS change if desired. For example, if the user has already chosen a page style, they probably do not want it to change automatically. Therefore the default behavior is to change dynamically only when there is no cookie and the user has not chosen a page style yet. You can get all options from the static read-only method StyleSwitch.PREFERRED_COLOR_SCHEME_CHANGE_BEHAVIOR. They are:
    • never never change the page style in response to OS color scheme changes.
    • always always change the page style when the OS color scheme changes. This can override a previously chosen user preference.
    • onlyWithoutCookie (default) change the page style on OS color scheme change only if the user has not yet chosen which page style to use.
  • (bool) reverseOrder list found styles from the document head in reverse order?
  • (object) switch All settings for the 'switch' widget
    • (bool) useSwitchIfPossible use the switch? This is only possible if there are exactly 2 available page styles (if you include naked style, it counts as one of the styles).
    • (bool) useRolesAsTitle Use the detected CSS style role as the title attribute for the switch element?
    • (string) labelClassName class attribute name for the wrapper element of the resulting widget.
    • (string) captionElementName element name for the switch widget caption. Only inline elements are supported, not block elements!
    • (string) visualSwitchClassName class attribute name for the visual switch element of the resulting widget.
    • (string) stateClassName class attribute name for the element that displays the switch state (default "on" / "off"… can be changed to any text)
    • (string) statusElementName element name for the element that displays the switch state. Only inline elements are supported, not block elements!
  • (object) select All settings for the 'select' widget
    • (bool) useRolesAsTitle Use the detected CSS style role as the title attribute for the option element inside the select?
    • (string) captionElementName element name for the caption of the resulting widget.
  • (object) radioList All settings for the 'radioList' widget
    • (bool) useRoleAsItemTitle Use the detected CSS style role as the title attribute for the input element?
    • (string) captionElementName element name for the caption of the resulting widget.

autoRun

(bool) Run the script automatically after import or insertion into the document? The default is yes, which is usually what you want. Only custom run function setup is a case where autoRun does not make sense.
